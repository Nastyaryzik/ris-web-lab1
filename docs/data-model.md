# Модель данных (ER-диаграмма и 3НФ)

## 1. Словарь терминов
| Термин курса | Термин моей темы |
| :--- | :--- |
| Ticket (Главный объект) | Слот консультации |
| Site (Справочник) | Дисциплина |
| User (Пользователь) | Студент / Преподаватель |

## 2. Сущности и атрибуты
### Сущность: Slot (Слот консультации)
*   **id** (PK) — машинный первичный ключ (число).
*   **number** — человеческий номер (например, CON-2026-001).
*   **dateTime** — дата и время консультации.
*   **status** — статус (New, InProgress, Closed, Cancelled).
*   **disciplineId** (FK) — ссылка на дисциплину.
*   **teacherId** (FK) — ссылка на преподавателя, создавшего слот.
*   **studentId** (FK, nullable) — ссылка на студента, который записался (может быть пустым).

### Сущность: Discipline (Дисциплина)
*   **id** (PK) — машинный первичный ключ.
*   **name** — название дисциплины (например, «Веб-программирование»).

### Сущность: User (Пользователь)
*   **id** (PK) — машинный первичный ключ.
*   **name** — ФИО или логин.
*   **role** — роль (Student или Teacher).

## 3. Связи (подписи словами)
*   Одна **Дисциплина** — много **Слотов** (1:N).
*   Один **Преподаватель** создаёт много **Слотов** (1:N).
*   Один **Студент** может записаться на много **Слотов** (1:N).
*   У нового **Слота** студент может отсутствовать (nullable FK).

## 4. Проверка 3НФ
Название дисциплины хранится в сущности **Discipline** один раз. Слот содержит только внешний ключ **disciplineId**. При переименовании дисциплины меняется одна строка, поэтому текст названия не дублируется в слотах.
